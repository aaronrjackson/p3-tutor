Context and memory in an agent

From Lesson 1. Token numbers are illustrations.

Terms

TermMeaning
TokenA small piece of text: a word, part of a word, or a character. About 3 to 4 English characters.
Context windowAll the tokens the model can use in one call, reply included. Rules, tools, messages and tool results all count.
StatelessThe model keeps nothing between calls. The program sends the full history each time.
SessionOne conversation. Its context is gone at the end.
Memory / noteFacts the program saves outside the context and loads back in.
Chunk, index, retrievalA small piece of a document; a prepared list for fast search; searching chunks and returning the best few.

Cost rule

Tokens sent in total = the sum of the input of every call. Old text is sent again at every later call, so a long tool result costs once per remaining step.

Three questions: where does it go?

  1. Needed at every step? Then it goes in the context (keep it short).
  2. Does it last past this session? Then it goes in saved notes.
  3. Too long to carry? Then it goes in a searchable store; only the best chunks enter the context.

Watch for

  • Memory is not automatic: the program saves and loads it.
  • A bigger window does not mean "send everything": cost grows and recall can drop.
  • Retrieval can return the wrong chunk. Tag chunks with machine and section. Test with real questions.
